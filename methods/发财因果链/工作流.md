# 发财因果链（比发财时间线多一个真）

**定义。** 发财时间线的终点是《详细行动与后果文档》：做了什么、后来发生了什么。发财因果链在它之上加三道关，把"做了什么 → 收入涨了"拆成一环一环，每环单独过关，过不了的环就写"缺口"或"证伪"，不许用叙事补。

| 关 | 要求 | 过不了怎么写 |
|---|---|---|
| 一、逐环证据 | 动作 → 直接后果 → 中间指标 → 用户/付费 → 收入，每一环各自有 URL 和数字 | 缺口：找过哪里、为什么没有 |
| 二、时间检验 | 动作日期必须早于后果日期，写出滞后；拼一张按月对齐的多序列时间表 | 后果先于动作 = 证伪；同月分不出先后 = 不能算实证 |
| 三、同类案例 | 凡判定"有效"的手段，找 ≥3 个其他产品同类操作的真实获利案例，每例要动作日期 + 前后各 3 个月的数字 + URL；反例也要列 | 不满 3 个有前后对照的 = "仅单例"；只有相关性的 = "相关但未证明先后" |

## 一、终点文档的固定结构（8 节）

1. **勘误**：上一轮被推翻或修正的说法，一条一行：原说法 | 本轮发现 | 证据 URL。
2. **对齐的月度时间表**：列 = 定价/额度变动 | 载体事件 | 代码引用数 | Agent 占比 | 搜索热度 | 用户数 | 教程播放 | MRR | 付费客户数，每个数字带出处。
3. **链条表（核心）**：每环一行，列固定：环 | 动作（日期） | 直接后果（数字） | 证据 URL | 强度（实证 / 推测 / 证伪 / 缺口） | 时间检验 | 同类案例（产品：动作→结果，数字，URL；≥3 个前后对照才标"已验证"）。
4. **手段验证结论**：每个手段一句判定：已验证 / 有条件有效（写条件） / 证据不足，附支撑案例数（前后对照 / 仅相关）和反例数。
5. **真实链条**：一段话 + 一张图式列表，每个节点标强度。
6. **对自家产品的含义**：只写由实证环推出的，推测环推出的标"推测"。
7. **缺口清单**：合并去重，每条写"找过哪里"。
8. **来源**：全部编号，Wayback 链接带时间戳。

## 三、Wayback 当主力工具的用法（本次实测）

| 用法 | 命令或地址 | 本次拿到了什么 |
|---|---|---|
| 定价页改在哪一天 | `https://web.archive.org/cdx/search/cdx?url=<站>/pricing&fl=timestamp,digest&collapse=digest&filter=statuscode:200`，再 `https://web.archive.org/web/diff/<ts1>/<ts2>/<url>` | 35 个版本对比，把"涨价 + 硬上限"从 2025/2026 纠正到 2024-06-21 至 09-12 |
| 第三方收入页快照 | `https://web.archive.org/web/<ts>id_/https://trustmrr.com/startup/<x>` | 发现"月收入"含年付不是 MRR；拿到 06-15、09-29、11-05 三个 MRR 和订阅数点 |
| 创始人推文图片 | `https://web.archive.org/web/2026*/x.com/<handle>/status/*`，图片走 pbs.twimg.com | 2026-03-18 的 MRR 图，补上 2025 全年 |
| 首页文案演变 | 首页按月快照 `collapse=timestamp:6` | "No Signup required" 到 2025-10-06 还在，11-14 变成 Sign up / Login |
| 成功页文案 | /success 快照 | "Create your own contact form" 加在 2023-02 至 09 之间 |
| llms.txt 谁先做 | 对几十个域名跑 `url=<站>/llms.txt&fl=timestamp,statuscode&limit=1` | 30 多家首次快照表；目标站的那份晚于 Agent 已在用的话术 |
| 列出站内曾存在的页 | `url=<站>/*&filter=original:.*(open|stats|pricing|limit|changelog).*&collapse=urlkey&fl=original,timestamp` | 找到已 404 的 /open 页，但图表数据没存档 |
| 对照组 | 同样的方法对竞品跑一遍 | Formspree 免费额度 1000 → 100 → 50 的时间线 |

**坑。** `http://web.archive.org` 这次全程失败，只有 `https://` 能用，且会间歇离线，curl 加 `--retry 3 --retry-delay 5`；首页计数器多是 JS 渲染，快照里抓不到；YouTube 快照抓不到播放数；old.reddit 整站不在 Wayback 里，Reddit 评论走 Arctic Shift。

## 四、浏览器规则（因事故定下）

研究 Agent 可以用用户的 Chrome（browser-use），但必须：保存 `new_tab()` 返回的标签 ID；读之前 `page_info()` 核对 URL 是自己开的；只用 `close_tab(自己的ID)`，绝不无参数调用；一次一个页面，不循环批量开；登录墙就停，已登录的站只读；能用 curl / WebFetch / Wayback 拿到的不开浏览器。本次一个 Agent 无参数关闭把用户的 5 个标签页关掉了。另外：用户邮箱不进任何请求头（SEC EDGAR 要求 UA 带邮箱，所以不直连 EDGAR）。

## 五、本次结果（第一个对象：Web3Forms）

- 报告：`结果/reports/Web3Forms 动作到收入逻辑链.md`（8 节，勘误 15 条，链条 16 环，227 个来源）。
- 笔记：`结果/research_notes/Web3Forms 动作到收入逻辑链/` 五份。
- 结论变化：上一轮"涨价 × 硬上限 × llms.txt 话术"三条全被推翻；真实结构是单价不动（$12.4–13.8）、付费人数 476 → 3,206；拐点 2025-10/11 三件事同月分不出先后，都不算实证；中间环"撞限 → 升级"是缺口。
- 成本：6 个 Opus Agent，约 210 万 token，约 2.5 小时。

## 六、和发财时间线的关系

发财时间线（01、02 文件）产出《详细行动与后果文档》；发财因果链以它为输入，产出《动作到收入逻辑链》。两份都要，先后顺序不能反：没有行动清单就没有链条假设。
