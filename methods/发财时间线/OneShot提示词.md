# 发财时间线 One-shot 提示词：对标产品营销动作全史调研

用法：把下面"提示词正文"整段粘给带 Agent 工具的 Claude Code，替换 `{}` 里的变量。它会自己拆题、并行派研究 Agent、汇总、重写、落成行动计划。单独一轮对话跑完，不需要中途追问。

变量：
- `{目标产品}`：如 Web3Forms（web3forms.com，创始人 Surjith S M）
- `{对标档案}`：你已有的档案页或笔记路径，如 https://msfdcszhd.com/s/web3forms.com/
- `{基线文件}`：本地已知数据的文件路径（收入、定价、流量），没有就写"无"
- `{自家产品}`：一段话说明自己的产品、现状、和目标产品的本质差异（成本结构、风险点）
- `{输出目录}`：绝对路径
- `{今天}`：日期

---

## 提示词正文

你是调研协调者。目标：挖出 {目标产品} 从上线到 {今天} 的完整营销动作史，回答"发布了什么产品、组件、集成和页面；在哪发布、怎么发布（标题、措辞、时间、数据）；每个动作带来了多少用户和流量；哪些动作没用；真正驱动增长和收入的机制是什么"，并修正 {对标档案} 里的错误说法。

**必交付物是一份《{目标产品} 详细行动与后果文档》**（第 6 步的规格）：每一个动作都要同时有"行动"（日期、地点、原文标题或措辞、文件路径）和"后果"（票数、访客、注册、付费、收入、星、播放量、commit 这类数字）和来源链接。其余产物（笔记、初稿、计划）都是为它服务的中间件。最后再落成 {自家产品} 的 90 天行动计划。

你自己不翻资料、不写报告，只做：建目录、写任务书、并行派 Agent、收摘要、抽查成品、核实对自家代码的指控。

### 第 0 步：基线
读 {基线文件} 和 {对标档案}。把已知的数字记下，之后所有任务书都写"读基线，往外找增量，不复述基线表格"。

### 第 1 步：建目录
`{输出目录}/research_notes/{目标产品} 营销动作全史/` 和 `{输出目录}/reports/`。

### 第 2 步：一次性并行派 5 个研究 Agent（model=opus，subagent_type=general-purpose）
每个 Agent 的提示词结构固定：一句话目标；6 到 8 个具体问题；建议来源；约束（时间范围、读基线、每条带 URL、推测标"推测"、缺口单列、简体中文、英文原话和代码照录）；输出路径。五个角度：

1. **发布动作史** `launch_history.md`：Product Hunt（每次的日期、标语、票数、maker 评论原文、当天排名）；Hacker News（Show HN、创始人评论）；Reddit（版块、标题、日期、分数、是否创始人自发、最早的一帖、被删的帖）；Indie Hackers（立项、里程碑、第一周和第一个月的访客/注册/付费/收入原话）；Twitter/X；访谈和播客里的里程碑和渠道归因原话；创始人自己写的教程文章。
2. **创始人产品矩阵** `product_matrix.md`：创始人的全部产品、模板、主题、工具、newsletter、社群，各自的上线日期和规模（星、下载、收入）；每个模板里目标产品的片段是不是预埋的（给出文件路径和行号）、README 有没有链接、有没有 "Powered by"；AppSumo 或其他团购的日期、价格、销量、评价；交叉导流是单向还是双向。
3. **组件与集成** `components_integrations.md`：官方 SDK/npm 包（发布日、各年下载）；免费工具；平台市场上架（Zapier、Make、n8n、Webflow、Framer、WordPress 等，逐个确认有无官方条目）；文档里每个框架的示例页；AI 时代产物（llms.txt、MCP、CLAUDE.md/AGENTS.md 提及数、Agent 署名 commit）；公开 changelog 的日期；GitHub 按年新增仓库数和按文件类型的引用数。
4. **SEO 与内容引擎** `seo_content_engine.md`：站点结构和程序化页面（对比页、平台页、模板页的数量和首次存档日期）；博客篇数和日期；关键词（品牌词占比、Breakout 查询）；外链（谁链了，创始人自己提的列表 PR）；AI 建站工具吐出片段的证据（commit 月度数、Agent 署名占比、社区帖子）；Google Trends 曲线和与竞品的比值；有无付费投放。
5. **第三方传播** `third_party_amplification.md`：YouTube 教程前 20 条（频道、标题、日期、播放量、是否放链接）；高星第三方模板和训练营作品集；Stack Overflow / Reddit / HN 上别人推荐的时刻（日期、分数）；newsletter 收录；目录站评价数；非英语社区；有无推荐/联盟计划和默认成功页这类被动扩散机制；把这些载体和收入里程碑按时间对齐。

研究 Agent 必须用的工具写进"建议来源"：Wayback Machine（CDX 接口列 URL：`web.archive.org/cdx/search/cdx?url=<站>/*&filter=original:.*<词>.*&collapse=urlkey&fl=original,timestamp`；首次存档时间写"存档≤"；注意 old.reddit.com 被 Wayback 排除，Reddit 只能读 www.reddit.com 的帖子页快照，新快照常是验证页，CDX 接口 503 要重试）、Arctic Shift（Reddit 作者全史；评论用按帖子 ID 拉评论树，全文搜索会超时）、`gh api search/code` 和 `gh search repos --created`、npm-stat、Google Trends、TrustMRR、YouTube 搜索。挡爬虫的站允许借本机 Chrome 读，读完关标签页。

### 第 3 步：收摘要，决定是否追补
只有缺口动摇主线时才追补一轮，且只追补一轮。

### 第 4 步：初稿 Agent（model=opus）
读全部笔记和基线，写初稿 `{输出目录}/reports/{目标产品} 营销动作全史.md`。要求：开头一张"全部有日期动作"的表（日期 | 动作 | 措辞/路径 | 结果数字 | 链接）；然后分章：发布期、占位期、片段被复制的几轮载体、没起作用的动作、对 {对标档案} 和基线的修正表（原说法 | 实际 | 依据）。同一次再写 `{输出目录}/营销计划.md`：按第 1–2、3–4、5–8、9–12 周排，每项写产出物（路径/URL/标题）、分发渠道、照抄的证据（笔记 + 日期 + 数字）、完成标准；列"不做清单"（目标产品证明没用或从没做的事）；列每周看的指标和取数命令。计划必须先写"哪些不能照抄"（{自家产品} 和目标产品的本质差异）。

### 第 5 步：抽查与核实
看报告标题结构和结论段。报告或计划里凡是说"自家产品的代码有问题"的，逐条 grep 源码确认，确认了才转述。

### 第 6 步：产出必交付物《详细行动与后果文档》（model=opus）
派 1 个 Agent 读初稿和全部笔记，写 `{输出目录}/reports/{目标产品} 营销动作 整理版.md`。这是整个流程的终点，规格如下，缺一不可：
- 风格：短句，一句一个事实，不要过渡句和"综上所述"；细节一个不少：日期、地点、原文标题、数字、文件路径和行号、来源链接；推测只标两个字。
- 固定八段：1 一页结论（≤10 条，每条带数字）；2 时间线（全部有日期动作，一张表，列为 日期 | 动作 | 具体内容（标题/措辞/路径） | 后果（数字） | 来源）；3 发布期；4 占位期；5 片段被复制的几轮载体；6 没起作用的动作（每项附证明它没用的数字）；7 修正表（原说法 | 实际 | 依据）；8 来源（编号，按笔记分组）。
- 每个动作必须同时写行动和后果；只有行动没有后果数字的行不合格，确实查不到就写"后果未知"并进缺口。
- 要求它逐条核对数字，回报与初稿矛盾之处。
- 之后任何追补（如用 Wayback 补 Reddit）都以附录形式接在这份文档末尾，不另开文件。

### 第 7 步：交付
把整理版报告、全史报告、营销计划发给用户，并用不超过 400 字回答："这个产品做对了什么才起的量"和"做对了什么才大幅增收"，两者分开答，分别给证据。

### 验收清单
- 《详细行动与后果文档》存在，八段齐全，时间线每行都有后果数字或"后果未知"
- 每条结论下有 URL；推测有标记；缺口有清单
- 时间线行数 ≥ 50，来源 ≥ 200
- 修正表里每条有依据
- 计划里每项动作引用了具体证据，且"不做清单"存在
- 对自家代码的指控都经 grep 核实
