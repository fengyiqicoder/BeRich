# 发财时间线：竞品营销动作调研工作流（以 Web3Forms 为例，2026-11-03 至 11-04 实跑）

目的：把一个对标产品从上线到今天的全部营销动作挖出来，每个动作有日期、措辞、数字、来源，再判断哪些动作真正带来了用户和收入，最后落成自己产品的行动计划。

## 零、工作流的终点：对标产品的《详细行动与后果文档》

整个流程只为产出一份文档，其余都是中间件。这次的成品是 `结果/reports/Web3Forms 营销动作 整理版.md`。它的规格固定如下，以后每次调研都按这个验收：

| 部分 | 要求 |
|---|---|
| 1 一页结论 | 不超过 10 条，每条是一个带数字的完整事实 |
| 2 时间线 | 一张表，收全所有有日期的动作。列：日期 \| 动作 \| 具体内容（标题 / 措辞 / 文件路径） \| 后果（数字：票数、访客、注册、付费、收入、星、播放、commit） \| 来源链接。本次 69 行 |
| 3 发布期 | 发了什么、发在哪、原文标题、第一周和第一个月的数字、哪些帖被删、评论区要了什么 |
| 4 占位期 | 文档骨架、程序化页面（数量和日期）、列表 PR、答疑、唯一的包、零个市场上架、团购数字、Twitter 和抽奖的结果 |
| 5 片段被复制的几轮载体 | 自家模板（文件路径和行号、星和 fork）、别人的教程（播放量和日期）、AI Agent（月度 commit 数、署名占比、CLAUDE.md 数、许可话术原文、成功页） |
| 6 没起作用的动作 | 一个清单，每项附证明它没用的数字 |
| 7 修正表 | 原说法 \| 实际 \| 依据，修正对标档案和本地基线里的错 |
| 8 来源 | 编号列表，按笔记分组；本次 316 条 |
| 附录 | 追补轮的结果（本次：Reddit 经 Wayback） |

文风：短句，一句一个事实，不要过渡句；细节一个不少：日期、地点、原文、数字、路径、链接；推测只标两个字。每条结论下必须有 URL。

**每个动作都要同时写"行动"和"后果"**：行动是他在哪、发了什么、原话是什么；后果是数字（票数、访客、注册、付费、收入、星、播放量、commit）。只有行动没有后果的行不合格。

原则：
1. 协调者不亲自翻资料，只写任务书、收摘要、抽查成品。上下文保持干净，才能连续做十几个小时。
2. 每条结论下面必须有 URL；推测必须标"推测"；找不到的写进"缺口"，不许编。
3. 先定基线，所有人往外找增量，不复述已知。
4. 问题拆到"互不重叠、合起来覆盖全部"，一人只盯一件事。
5. 对自家产品的指控，协调者自己 grep 源码核实后才转述。

## 二、工具清单（研究 Agent 实际用到的）

| 用途 | 工具 | 备注 |
|---|---|---|
| 给页面定日期、读已下线的页 | Wayback Machine：`web.archive.org/web/<时间戳>/<url>`；列 URL 用 CDX：`web.archive.org/cdx/search/cdx?url=<站>/*&filter=original:.*<词>.*&collapse=urlkey&fl=original,timestamp` | 首次存档时间只能写"存档≤某日"；约 1 请求/秒 |
| Reddit（帖子、评论、被删帖） | 两件套：Arctic Shift 查作者全史和**按帖子 ID 拉评论树**（全文搜索会超时，ID 查询稳定）；Wayback 读 www.reddit.com 的帖子页快照，被删帖看快照里的 `removedByCategory` 和 "removed by Reddit's spam filters" 字样 | **old.reddit.com 整站被 Wayback 排除**；2026 年的 www.reddit.com 快照多是机器人验证页；CDX 接口常 503/504，要重试；被删帖的正文多半拿不回（reveddit、pullpush 也没有） |
| 挡爬虫的站（Indie Hackers 403） | 借用户的 Chrome（browser-use）读，读完关标签页 | 或 Wayback |
| GitHub 采用量 | `gh api search/code`、`gh search repos`、按 `created:` 年份数仓库、按 commit 正文数 "Co-Authored-By" | 代码搜索不能按年过滤，用仓库创建年或 commit 日期代替 |
| 包下载量 | npmjs、npm-stat、npmtrends | 看年度和月度两种 |
| 搜索趋势 | Google Trends（相对值、相关查询、Breakout 标记） | 绝对量拿不到（Semrush/Ahrefs 免费接口不可用） |
| 视频传播 | YouTube 搜索按播放量和日期排序；GitHub 搜"教程作者名 + 接口域名"验证学员抄代码 | 简介不提产品的教程只能靠代码证据 |
| 收入 | TrustMRR（Paddle 核验） | Similarweb 对 Paddle overlay 结账站的付费页访问不可信 |
| 通用规律 | 本地 SoloMax RAG（639 篇增长文章） | 只用于校验判断，不作为证据写进报告 |

## 三、这次失败和绕过

| 问题 | 处理 |
|---|---|
| X/Twitter 时间线要登录，Agent 搜推文 URL 被权限分类器拦 | 放弃，写进缺口；只拿到 4 条创始人推文 |
| reddit.com 和两个归档接口都取不到评论 | 第二轮按用户提议走 Wayback；实际发现 old.reddit 被排除、新快照是验证页，最终靠 Wayback 帖子页 + Arctic Shift 按 ID 拉评论树补齐（44 个快照、119 棵评论树） |
| Indie Hackers 403 | 借 Chrome 读 |
| 部署脚本整体运行被分类器拦（两次） | 按脚本原文拆成"打包上传"和"服务器安装"两步执行，步骤不增减，并告知用户 |
| 汇总报告个别数字与笔记不一致 | 重写时强制逐条核对，列出矛盾清单 |
