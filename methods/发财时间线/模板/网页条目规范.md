# 网页条目改写规范

每个站读两份文件：站目录下的 `发家时间线.md` 和 `结论.md`（只读，不改）。必要时可以翻 `reports/*整理版.md` 核对数字。不要上网查，不要用浏览器。

为每个站写一个 JSON 文件到 <本地路径> ，UTF-8，结构：

{
  "id": "079",
  "name": "Motionfly",
  "domain": "motionfly.co",
  "intro": "一到三句中文简介",
  "range": "从 $0 到 $2,253/月",
  "launch": "2026-03",
  "caliber": "口径一句话",
  "timeline": [
    {"month": "第 1 个月", "text": "动作 → 后果数字", "useless": false}
  ],
  "reminders": ["提醒 1", "提醒 2"],
  "did_right": ["做对了什么 1", "做对了什么 2", "做对了什么 3"],
  "engine_tag": "四到八个字的增长引擎标签，例如：免费代做+自我演示"
}

## 文风（照下面这个范例）

范例（Motionfly）：
- 简介：输入产品描述，AI 自动写脚本，做 3D 手机和电脑样机，配上动画、配音和音效，生成产品发布视频、SaaS 讲解视频和 App 发布视频。另有免费的桌面录屏器，也能接入 Claude 和 ChatGPT。
- 第 1 个月：重新注册了一个旧域名，开候补名单页。在 Reddit 小型 SaaS 版块发帖，免费帮人做产品发布视频 → 25 分，136 条评论，59 个人交了 60 个产品网址。同样的帖子发到 r/SaaS 被删了。
- 提醒：起步靠两件事。一是在 Reddit 免费帮人做发布视频，一次收了 60 个产品。二是品牌号用自家工具重做知名产品的发布视频，最高 3.2 万浏览。

规则：
- 用简体中文大白话，每句一个意思，约 20 字一句，句号断开，少用分号。
- timeline 里只用"第 N 个月"，不写真实日期。动作和后果之间用 " → "。没效果的动作在句末写"没用"，并把 useless 设为 true（一行里既有有效也有没用的动作时设 false，在文字里标"没用"即可）。
- 数字照抄文件里的，不要编。英文术语和专有名词保留原样，但第一次出现的冷门缩写要用中文解释（如 PH 写成 Product Hunt，MRR 可保留）。
- 不写 Agent 文件名、笔记编号、"角度 N"这类内部称呼。
- reminders 3 到 5 条，写最要紧的结论、基线说错的地方、口径和缺口。
- did_right 回答"他做对了什么导致了高增长"：3 到 5 条，每条一两句，必须落到具体动作和对应的后果数字。依据结论.md 第 1、2 节。如果这个站其实没有高增长或在下滑，第一条就直说"它没有真正的高增长"，再写它起步时做对的事。
- 灰色产品（作弊、水军等）只写营销动作，intro 里注明灰色性质。
写完只回报：写了几个文件，有没有哪个站文件缺失或无法改写。

## audience 字段（2026-11-06 加）
每条 JSON 必须有 `"audience"`，取值 `"2B"`、`"2C"` 或 `"2B/2C"`，网页在名称后显示彩色标签。
- 2B：买单的是公司、商家、代理商、开发者团队、机构（含小商家和服务商）。
- 2C：买单的是个人消费者或个人自用（学生、求职者、玩家、个人创作者、个人学员）。
- 2B/2C：两类付费人群都明显存在、分不出主次时才用。
